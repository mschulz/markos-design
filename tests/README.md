# Validation boundaries

The existing tests protect archived v0.2 behavior and import safety. They do not establish v0.3 acceptance and do not impose PARA, Markdown authority, DuckDB or the old application on the new design. Preserve them with the archive; do not extend the legacy product as the new foundation.

The independent runtime now owns 294 tests (177 unit/boundary, 103 real PostgreSQL, 13 real broker/database cases and one dedicated broker-volume-loss case) under `services/runtime/tests/`, installed without the root project. See [[MarkOS v0.3 M0-A Contracts and Configuration]]. [[MarkOS v0.3 M0 Implementation Plan]] defines A01–A20: dependency/config isolation, strict event/identity contracts, real PostgreSQL transactions/roles, RabbitMQ confirms/returns, durable handoff, idempotency, watchdogs, scheduling/fencing, replay/deletion and lifecycle/pressure evidence.

Use synthetic sources and isolated broker/database instances; no personal folders, real accounts or provider effects. Legacy regressions and PR #6's pure contract tests are prior evidence, not proof of broker/database durability. Run new gates independently in CI. M0-A supplies A01–A03 evidence; M0-B supplies A04–A05 real-database evidence. Integration requires an explicit dedicated local test DSN and creates/drops synthetic databases/roles. CI requires it. M0-C supplies A06–A10 transport evidence, including real confirms/returns/fan-out/redelivery and operational review. CI requires both services; local absence of RabbitMQ skips its 13 normal broker cases explicitly; the Docker volume-loss case has its own required CI job. M0-D supplies A11/A12 synthetic execution/schedule evidence and A13 database-failure evidence; M0-E supplies A14–A16 synthetic replay/retention/deletion/permit evidence. Real provider/action approval, erasure/restore and A17–A20 operations remain future gates. See [[MarkOS v0.3 M0-E Replay and Retention]]. See [[MarkOS v0.3 M0-D Execution and Scheduling]]. See [[MarkOS v0.3 M0-C RabbitMQ Transport]]. See [[MarkOS v0.3 M0-B Durable Storage]].
